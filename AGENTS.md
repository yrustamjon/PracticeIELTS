Definition of Done: connected persisted behavior, permission/error states, passing relevant tests and updated task/docs. Do not merge/deploy or force push. User permits pushes to main.

## Persistent work over SSH — user preference
The user connects from a phone over SSH and requests that execution tasks run in a persistent server-side tmux session by default, so phone/SSH disconnection does not terminate the worker. This preference applies to future tasks in this checkout; explanatory answers alone do not require another worker.
- Check existing task sessions first. Reuse the worker handling the task; do not start duplicate agents editing the same checkout. If already inside tmux, continue there.
- When handing work to a persistent Codex worker, first save the objective, user constraints, completed work, verification evidence, source/artifact paths and concrete next actions in a handoff document and docs/STATUS.md. Preserve existing edits and all approval/deployment boundaries.
- Launch the worker with normal sandbox and approval controls. Verify it received the handoff and actually started work before reporting success. Once ownership transfers, the parent stops task edits; independent user-requested preference/documentation updates are allowed.
- Report the tmux session name and exact attach command. Reading currently uses `tmux attach -t practiceielts-reading`; verify availability rather than assuming an earlier session still exists.
- Keep resumable checkpoints and honest completion status. tmux protects against SSH disconnection, not server shutdown, server network loss, account limits or approval waits. Never promise guaranteed completion or silently bypass permissions to keep work running.
