# Architecture
React/TypeScript/Vite + Router + TanStack Query + Zustand + Tailwind frontend → /api/v1 → Django REST Framework → PostgreSQL. Redis brokers Celery; FFmpeg validates audio. Private local storage for development; S3-compatible storage configurable for deployment. Never expose object-store credentials. Browser uses same-origin Vite API proxy; JWT short-lived access tokens in memory, HttpOnly refresh cookie. Authorization enforced by DRF.

Backend modules: accounts (custom user/role); learning (categories, material metadata, versioned transcripts, audio, sessions, responses, audit); services (audio validation and deterministic comparison); processing owns speech jobs/ASR/alignment/segmentation; exams owns questions/PDFs/attempts/scoring; future integrations stay separate. Frontend: app shell/routes, reusable UI, feature pages, API client/auth store. This initial bounded learning module can be split by domain as complexity increases.

Relationships: User → PracticeSession → immutable TranscriptVersion → TranscriptSegment. Material → Category (arbitrary self parent, cycles forbidden), AudioAsset and TranscriptVersion. StudentResponse references session/version and stores raw answer and comparison. Staff writes emit AuditLog. Published versions are immutable; edits produce a new version. LearningProgress derives from persisted checked responses rather than a second source of truth. MistakeRecord/notes are later milestones.

Audio stays original: segment windows in milliseconds, no per-sentence duplicate files. Validate file via ffprobe without shell interpolation; authenticated streamed Range delivery. Publish is gated on rights metadata, audio and validated non-overlapping segments. Exam playback uses the separate restricted authorization path described below.

ProcessingJob, Question/QuestionOption/AnswerKey and MockAttempt are implemented by the extension below. MistakeRecord resolution, VocabularyNote and phoneme alignment are future work. Speech and word-anchor reference alignment run asynchronously; uncertain results require editor review.


## Real ingest and exam extension
`processing` owns durable ProcessingJob records, real faster-whisper transcription, separate AlignmentService and timestamp-driven segmentation. A successful job produces a new immutable TranscriptVersion and Segment.words; it never publishes itself. ASR/reference errors and unmatched anchors are visible for review. Word-level timings drive Easy chunks; Medium uses one sentence, Hard uses at most three. PracticeSession.grouping_version preserves historical grouping semantics.

`exams` owns private QuestionDocument, immutable QuestionSet versions, normalized Question/QuestionOption/AnswerKey and MockAttempt. The material's published transcript and question-set pointers move together on approval. Attempt answers, deadlines and score are persisted, keys are omitted before submission, and raw PDF/extracted text stay editor-only. Text question sets expose no student PDF pages. Legacy PDF endpoints retain approved-page authorization for historical API compatibility; the current student Mock never renders images. Active exams block the same material's generic study, hints and media routes. Exam audio uses an owned, single-use ticket and the original recording.

PDF intake previews source pages only for editors. A bounded numbered-text parser creates editable drafts from selected pages, without answer inference or arbitrary layout reconstruction. Teachers review actual text, instructions, options, tables and keys; scanned/ambiguous papers require manual authoring. QuestionSet.presentation defaults to text; migration labels historical rows legacy_pdf without mutating their content or attempts. Timed/untimed choice is a property of the attempt, not duplicate materials. UI uses the same navy/teal shell across library, content studio, Practice, text exam and results. Reading/Writing/Speaking remain read-only future placeholders.

## Native HTML exam reference
QuestionSet.sections stores bounded, sanitized [{part,html}] content in each immutable question-set version; presentation=html renders it as native React elements with numbered live answer controls. Django's explicit HTML tree parser accepts part1–part4 groups from authorized teacher uploads, strips scripts/styles/active attributes/remote media, and maps source controls to markers rather than executing embedded application code. Keys are never extracted from scripts. The API validates marker ownership by part and full question/option coverage. The client allowlists elements a second time and binds controls to the same persisted MockAttempt.answers state. Existing PDF/text versions are unchanged. The white exam toolbar and bottom active-part navigation follow the uploaded visual reference while keeping the wider app's PracticeIELTS branding.

## Bounded exam viewport and scoped PDF styles
The active exam shell is a viewport-height flex column. Toolbar and the portal-hosted question navigation occupy fixed layout space; main question content alone scrolls. Review controls/counters are removed from active Mock. Current-part PDF pages render in an approved-page stack or responsive two-column grid, with deferred loading as pages approach the viewport. Only PDF text-layer CSS scoped beneath .pdf-original-page is imported; full pdf_viewer.css is excluded because its global .sidebar rules corrupt the normal app after a PDF component is loaded.

## Approved collection/test workflow

`ListeningTest` belongs to a category/book and owner. `TestPart` binds exactly one Material to a test/Part number (1–4), enforced with uniqueness/range constraints. Existing standalone Materials retain their routes, versions and student history. The Material editor is presented in separate steps, while library/test/admin pages use the approved nested card layout.

Publication of four Parts schedules `learning.tasks.assemble_listening_test`. The worker serializes the test and its Part material rows, captures published version/question-set IDs, decodes actual whole recordings with FFmpeg and joins their PCM frames. Frame-derived offsets rebase transcript/word times. Text/HTML/PDF question versions are copied with sequential Full numbering; PDF output contains only approved pages with rebased field geometry. No speech recognition results or timestamps are invented by assembly. Source Part assets and historical publications remain intact. A directly authored Full recording has an empty assembly signature and is not replaced by automatic Part updates; explicit assembly remains available through the API.

Assembly failures preserve the prior Full publication and report an editor-visible error/retry state. A test with four transcripts but incomplete questions offers Full Practice only. Mixing question presentations requires correction before Full question assembly. Book/test/Part writes enforce ownership in addition to role checks. Active-exam guards expand to all recordings within the test so sibling Practice/transcripts cannot reveal its answers.

The Practice editor and feedback expand in normal document flow, with page scrolling when content exceeds the viewport. The textarea grows with its text and remeasures on viewport resize; the editor has no nested scrollbar or capped height. The exercise list retains pagination and its own bounded list area. Difficulty switches and navigation await persisted drafts and retain version-pinned server behavior. Main route/query navigation resets document scroll. Mock libraries retain explicit links to active attempts.

## Book → Volume → Test → Parts navigation

The admin has one context-driven path. Category roots are presented as Books (Cambridge), their leaf child categories as Volumes (Cambridge 10), then ListeningTest and TestPart records. A book view renders its volume cards; a volume view renders tests; a test view renders Parts. Creation fixes its parent from the current context rather than asking users to choose another destination. The API rejects test creation in root/nonleaf categories.

BookHierarchy is shared by the studio and grouped material editor. It fetches owned test metadata as well as categories, displays all four levels and actual Part readiness, expands the active path and retains sibling books, volumes and tests. Volume/test/Part pages share the full-width title/workflow and the same hierarchy/content grid; editor forms use the available content width. Part actions use existing authorized material endpoints. Independent materials remain compatible. Misclassified existing root tests can be moved to a volume without replacing material IDs or student history.

## Timed and untimed Mock playback

Timed attempts retain one-play ticket delivery and test-wide study restrictions. Untimed attempts may renew owned tickets, replay, seek and return while keeping persisted answers. Multiple untimed Parts and Full attempts can remain active. During a timed attempt, sibling untimed sessions and submitted history are blocked on retrieval, listing, restart and approved PDF routes; a rejected restart cannot submit saved work. The client loads a private blob and reuses it for local pause/replay. Answer keys remain hidden until submission.

Queued Full assembly can be explicitly retried. A ready Full with an unchanged source signature is reused, including after a retry waited for another worker's build. Workers must register `learning.tasks.assemble_listening_test`; restarting outdated local workers and retrying recovers dropped tasks without replacing source Part publications.

## Transcript correction boundaries

Review commits a finished time entry on blur/Enter, keeping intermediate typing local. The edited interval is authoritative. Adjacent end/start edges are trimmed only when needed to leave a 50ms gap; wider pauses are preserved. The operation refuses to erase a neighboring interval and leaves a visible validation warning. Timing-only Undo preserves text edits. Removing a draft row has a separate Undo; appending cannot create a zero-length interval at the recording end.

The transcript API independently validates nonempty text, integer milliseconds, positive/nonoverlapping intervals and measured audio bounds. Prior word anchors are looked up within the same material/audio/version by segment ID (or unchanged interval for older clients), rather than row index. Deleting a row therefore preserves valid anchors on later rows. Text corrections retain the existing alignment path; changed boundaries discard obsolete word anchors and require review. Every save creates a new transcript version, preserving published versions and student version pins.

## Easy Practice playback timing revisions

PracticeTimingRevision stores append-only interval override snapshots for one TranscriptVersion/grouping_version, with creator/time and an audit event. PracticeSession.timing_revision pins playback independently of immutable transcript content. Conditional uniqueness constraints preserve one original session and one session per correction snapshot for each user/material/version/difficulty/grouping; a check constraint limits revision pins to Easy. The timing write service locks the material and current session, validates administrator ownership, current publication, expected/latest revision and audio/neighbor boundaries, then advances the active admin session without replacing answers/responses. Other sessions retain prior timing; new Easy starts use the latest snapshot. Unpublished transcript editing remains independent.

## Super administrator settings and audit access

The existing Django superuser flag is the sole authority for account management, destructive content actions and audit access. The application creates delegated administrators with ordinary content privileges and no Django staff/superuser access; Django UserAdmin additionally refuses non-superusers to prevent privilege escalation through existing staff permissions. Auth responses expose capability flags solely for UI rendering; DRF independently checks permissions.

Profile settings provide validated own-password changes and superuser-only paginated administrator/activity controls. Password changes lock the user, validate the current/new password, blacklist outstanding refresh tokens and return a new token/cookie pair. SimpleJWT checks the stored password fingerprint on access authentication and the custom refresh endpoint checks it before rotation, invalidating previous sessions immediately. AuditLog gains an additive details JSON field; safe request metadata and account target identifiers augment immutable prior events. No passwords, request payloads or query strings enter audit metadata. Existing protected publications, historical responses and media remain unchanged.

## Revalidated private media
Study audio and isolated approved PDF pages support private browser caching with ETag revalidation after access checks. PDF extraction additionally uses the dedicated Django pdf_pages local-memory cache (10-minute TTL, 16 entries, at most 2 MiB per entry per API process). Keys include document ID, file identity/size/modified time, page and extraction format version. The cache contains derived PDF bytes, never authorization decisions; storage originals remain authoritative. Redis is not used for large media blobs. Ticketed exam audio keeps no-store/single-use behavior. First audio playback still awaits full blob download; caching improves subsequent requests, not first-download network latency. Browser eviction or credential/header changes may cause a fresh download.

## Progressive private study playback
AudioPlayer authorizes canonical /api/v1/audio/<id>/stream/ sources via the Bearer-only playback POST, then gives the original stream URL directly to the native audio element. A ten-minute signed HttpOnly cookie supplies scoped read authentication since native media cannot set an Authorization header. The cookie includes user ID and a password-derived session hash; current user activity, storage permissions and timed study guards are checked on every native Range request. Account refresh retains the grant; login/logout clear it. The player renews while mounted, permits play without full download, reports actual buffered time coverage/waiting and retries failed authorization/load. Noncanonical preview sources retain the prior blob fallback. Exam playback is unchanged. Redis is not involved in transporting media.


## Native Mock recording delivery
Mock now assigns the attempt-scoped authorized URL directly to HTMLAudioElement, allowing playback before the response finishes. It no longer assembles the complete audio blob in browser memory. Start grants carry signed HttpOnly cookies, accepted only by the exam audio action. Timed single delivery remains enforced under a database row lock; untimed delivery supports ranges for seeking and a longer grant. X-Accel-Buffering:no prevents nginx response buffering. Browser waiting/playing/error events drive loading feedback; server duration supplies a fallback when container metadata is unavailable. Timed connection loss still cannot restart playback, matching the existing restriction.

## Public Mock result snapshots
SharedMockResult holds one UUID capability link and JSON snapshot per submitted MockAttempt. The owner-authorized share action locks the attempt, creates/reuses the snapshot or deletes it to revoke access; recreation uses a new UUID. The anonymous read-only endpoint uses an explicit allowlisted result projection with category ancestry, test/Part, score and question-by-question answers/corrections/options. It omits user identity, source documents, media, transcript and private IDs. Public frontend route is outside Protected, fetches without credentials and renders text using React. Responses are no-store/noindex. Published question/transcript versions and saved attempts are unchanged.
